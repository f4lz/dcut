# THEORY

## Вопрос 1. Дженерики: определение, отличие от any, пример с ограничением

**Дженерик** (generic) - это параметр типа, который позволяет писать функции, интерфейсы и классы, работающие с разными типами данных, но при этом сохраняющие связь между входными и выходными типами. Конкретный тип подставляется в момент использования, а не в момент объявления.

**Отличие от `any`:** `any` полностью отключает проверку типов - компилятор перестаёт что-либо гарантировать, и любую операцию над значением можно выполнить без ошибки, даже если она в рантайме упадёт. Дженерик, наоборот, сохраняет типобезопасность: тип неизвестен заранее, но фиксируется на конкретном вызове, и TypeScript продолжает проверять соответствие типов внутри функции и в месте её использования.

```ts
// any - теряем всю информацию о типе
function firstAny(arr: any[]): any {
  return arr[0];
}
const a = firstAny([1, 2, 3]); // a: any, .toFixed() не проверится

// generic - тип сохраняется
function first<T>(arr: T[]): T {
  return arr[0];
}
const b = first([1, 2, 3]); // b: number
```

**Пример с ограничением (`extends`):** ограничение сужает допустимые типы до тех, что удовлетворяют условию, и позволяет безопасно обращаться к их свойствам.

```ts
interface HasId {
  id: string;
}

function findById<T extends HasId>(items: T[], id: string): T | undefined {
  return items.find((item) => item.id === id);
}

// подходит любой тип с полем id: string, например Slide из entities/slide
findById(slides, "1");
```

## Вопрос 2. `type` vs `interface`: различия, критерии выбора, `extends`

Оба инструмента описывают форму данных, и для большинства объектных типов взаимозаменяемы, но есть различия:

- **Расширение.** `interface` расширяется через `extends`, `type` - через пересечение (`&`). Интерфейсы также можно объявлять несколько раз с одним именем - TypeScript автоматически объединит их (**declaration merging**), у `type` так нельзя - повторное объявление того же имени будет ошибкой.
- **Что можно описать.** `type` - универсальный псевдоним: может описывать не только объекты, но и union, intersection, примитивы, кортежи, условные и mapped-типы (`KeysOfType` из вопроса 4 - это `type`, интерфейсом такое не выразить). `interface` предназначен именно для описания формы объектов/классов.
- **Реализация классом.** И `type`, и `interface` можно реализовать через `implements`, но `interface` для этого читается естественнее.

```ts
interface Slide {
  id: string;
  title: string;
}

interface CheckedSlide extends Slide {
  isChecked: boolean;
}

type SlideFormData = Omit<Slide, "id">; // алгебра типов - только type
type Status = "idle" | "loading" | "error"; // union - только type
```

**Критерий выбора:** если описывается форма объекта или контракт, который могут дополнять разные части кода (например, публичный API библиотеки) - `interface`. Если нужен union, intersection, кортеж, условный или mapped-тип, либо алиас для примитива - `type`. В прикладном коде это часто вопрос конвенции команды; в этом проекте `interface` используется для сторов и пропсов компонентов, `type` - для данных и производных типов (`SlideFormData`).

## Вопрос 3. Intersection и Union: разница, работа со свойствами, type guard

**Union (`A | B`)** - значение является **одним из** перечисленных типов. Доступны только свойства, общие для всех типов объединения (иначе TypeScript не может гарантировать, что свойство существует).

**Intersection (`A & B`)** - значение одновременно удовлетворяет **всем** перечисленным типам. Итоговый тип содержит объединение всех свойств из `A` и `B` - грубо говоря, "и то, и то сразу".

```ts
interface Loading {
  status: "loading";
}
interface Loaded {
  status: "success";
  data: string;
}

type State = Loading | Loaded; // union - либо Loading, либо Loaded
type WithTimestamp = Loaded & { fetchedAt: number }; // intersection - оба набора свойств сразу

function render(state: State) {
  state.status; // доступно всегда - общее свойство
  // state.data;   // ошибка: свойства data нет у Loading

  if (state.status === "success") {
    state.data; // здесь TypeScript сузил тип до Loaded - это и есть type guard
  }
}
```

**Type guard** - это проверка в рантайме (`typeof`, `instanceof`, сравнение поля вроде `status`, или пользовательская функция `value is T`), по результатам которой TypeScript **сужает** union до конкретного варианта внутри блока кода.

## Вопрос 4. Разбор типа `KeysOfType`

```ts
type KeysOfType<T, U> = {
  [K in keyof T]: T[K] extends U ? K : never;
}[keyof T];
```

1. `keyof T` - объединение всех имён свойств `T`.
2. `[K in keyof T]: ...` - mapped type проходит по каждому ключу `K` из `T` и строит новый объектный тип с теми же ключами.
3. `T[K] extends U ? K : never` - для каждого ключа проверяется тип значения: если `T[K]` совместим с `U`, значением в новом типе становится сам ключ `K` (как строковый литерал); если нет - `never`.
4. Получается промежуточный объект, где каждому ключу сопоставлено либо его собственное имя, либо `never`.
5. `[keyof T]` в конце - indexed access по всем ключам этого промежуточного объекта, который "собирает" все значения в union. Поскольку `never` в union "исчезает" (union с `never` равен исходному union без него), в результате остаются только те ключи, чьи значения соответствовали `U`.

Пример на `Slide` из проекта (`{ id: string; title: string; annotation: string; isChecked: boolean }`):

```ts
type StringKeys = KeysOfType<Slide, string>; // "id" | "title" | "annotation"
type BooleanKeys = KeysOfType<Slide, boolean>; // "isChecked"
```

Практическое применение - типобезопасные утилиты вроде "взять только строковые поля формы" или "поля, которые можно сортировать как числа".

## Вопрос 5. Утилитарные типы: `Partial`, `Pick`, `Omit`, `Record`, `Readonly`

- **`Partial<T>`** - делает все свойства `T` необязательными.

  ```ts
  function updateSlide(id: string, patch: Partial<Slide>) {
    /* ... */
  }
  updateSlide("1", { title: "Новый заголовок" }); // остальные поля можно не передавать
  ```

- **`Pick<T, K>`** - создаёт тип, оставляя только перечисленные ключи `K` из `T`. Применяется, когда нужен "срез" существующего типа без дублирования полей.

  ```ts
  type SlidePreview = Pick<Slide, "id" | "title">;
  ```

- **`Omit<T, K>`** - обратная операция: берёт `T` и исключает перечисленные ключи. Именно так в проекте определён `SlideFormData` - форма добавления слайда, где не нужны `id` и `isChecked`, которые генерируются автоматически.

  ```ts
  type SlideFormData = Omit<Slide, "id" | "isChecked">;
  ```

- **`Record<K, V>`** - строит объектный тип с ключами из `K` и значениями типа `V`. Удобен для словарей/мапов с фиксированным или ограниченным набором ключей.

  ```ts
  type SlidesById = Record<string, Slide>;
  const slideStatusLabels: Record<"idle" | "loading" | "error", string> = {
    idle: "Ожидание",
    loading: "Загрузка",
    error: "Ошибка",
  };
  ```

- **`Readonly<T>`** - делает все свойства `T` доступными только для чтения, попытка присвоить значение приведёт к ошибке компиляции. Используется для защиты данных от случайной мутации, например состояния стора или пропсов компонента.

  ```ts
  function renderSlide(slide: Readonly<Slide>) {
    // slide.title = "x"; // ошибка компиляции
  }
  ```
